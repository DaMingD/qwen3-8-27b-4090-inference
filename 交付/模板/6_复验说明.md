## 和赛方流程的差异

这些都已如实记录，复测时请使用相同设置：

1. **性能测试加 `--tokenizer`。** 和官方基线文档同口径。赛方脚本默认用 tiktoken，分词不同，结果可能不同，默认口径我们没有完整运行。
2. **IFBench 客户端超时 3600 秒。** 赛方 `accuracy_config` 只设 `max_tokens`，`--request-timeout` 不进入精度配置，于是用 OpenAI SDK 默认的 600 秒。请求不是流式的，30 tok/s 时约 18,000 token 以上的回答会被断开重采，按源码推算一题最多约 2.5 小时，次数用完整轮报错。基线的最长回答是 24,497 token，已经超过这个限制。`工具/accuracy_run.py` 只改这一个值，不修改赛方文件。用赛方默认超时复测也能运行，但耗时更长，分数可能因重采而不同。
3. **`--max-model-len 40960`。** 官方启动命令的 32768 过不了赛方脚本的上下文检查。
4. **基线 IFBench 是混合口径。** 89 题在 600 秒超时下生成，11 题在 3600 秒下生成，方案 A 全程 3600 秒。

## 从零复现

**第一步，准备赛方脚本。** 把赛方 `eval/` 放到 `参赛资料/eval/`。本次使用的版本：`run.sh` SHA-256 `078a2677038dbf3590b0e148546962aa27b00ef8dd11a14bbc272a96d8bc00fb`，`runner.py` SHA-256 `66d30de4f2f4a39b7243226d76f8be95a5e2e44ebe9e26e7c7e4f45bfe0b77ab`。第一次运行 `run.sh` 时会交互确认，安装 uv 和评测工具。我们的自查共用了已安装的评测工具环境，这一步没有重做。

**第二步，装环境。** 需要约 20GB 磁盘和网络：

```bash
WORK=$HOME/uclode bash 工具/setup_env.sh
```

安装脚本默认按仓库的 `交付/环境/requirements.lock` 安装全部锁定依赖，并运行 `pip check`、逐行比对安装后的清单。`REQUIREMENTS_LOCK` 可指定其他清单；缺少清单或比对不一致时退出失败。一级复验明确使用原环境的 `requirements.lock`，避免重建时自动升级间接依赖。

本次首次独立构建的权重分片哈希一致，但 filelock、openai、python-multipart 三个依赖自动升级，依赖一致性未通过。随后按原锁定清单修复该独立环境，安装后清单逐字节一致且 `pip check` 通过；首次失败记录保留在 `before_dependency_repair/`。这属于首次独立构建后的修复，不是第二次从零构建；GPU 验收仍由二级完成。

**第三步，转换权重。** 只有最终配置是 CUTLASS 才需要，只用 CPU，约 5 分钟，约 29 GiB：

```bash
$HOME/uclode/venv-vllm/bin/python 工具/convert_fp8.py --bf16 /model/ModelScope/Qwen/Qwen3.8-27B --fp8 /model/ModelScope/Qwen/Qwen3.8-27B-FP8 --out $HOME/uclode/models/Qwen3.8-27B-FP8-channel
```

**第四步，启动和测试。** 命令见[部署与配置说明](2_部署与配置说明.md)和根目录 README。完整性能约 80 分钟，IFBench 约 2.5–3 小时。

## 自查脚本

`工具/repro_check.sh` 把上面的检查分成两级，结果写入 `repro_build.json`、`repro_verify.json`：

```bash
bash 工具/repro_check.sh build
```

```bash
FINAL=cutlass REF=4=<并发4吞吐>,8=<并发8吞吐> bash 工具/repro_check.sh verify
```

`build` 隐藏所有 GPU，从零装环境、转换权重，比对权重哈希和依赖清单；`verify` 独占 GPU，先做 GPU 算子验收，再上机复测，约 15 分钟。两级都通过才算完成，`failed` 字段列出没过的项。
