## 关键参数

| 参数 | 官方配置 | 最终配置 | 依据 |
|---|---|---|---|
| `--max-num-seqs` | 4 | 8 | 并发 8 吞吐 {{fallback_c8_gain}}（{{fallback_c8_n}} 个请求），并发不超过 4 时不起作用，抢占次数为 0 |
| `--max-num-batched-tokens` | 默认 2048 | 默认 2048 | S=512 只提升 1.5%，S=128 下降 17.1%，减小预算的假设被否定 |
| `--linear-backend` | 自动（Marlin） | 通过门槛时为 `cutlass`，否则自动 | 见模型选型说明 |
| 模型目录 | 官方 FP8 | 通过门槛时为 per-channel FP8，否则官方 FP8 | 同上 |
| `--max-model-len` | 官方 32768 | 40960 | 官方值过不了赛方脚本精度阶段的上下文检查（提示词 + `max_tokens=32768`） |
| `--gpu-memory-utilization` | 默认 | 0.90 | 留给 KV 和状态约 11.74 GiB |
| `--kv-cache-dtype` | `fp8` | `fp8` | 不变 |
| `--speculative-config` | 无 | 无 | MTP 的质量和净收益没有完成验收，不开 |
| `--reasoning-parser` | `qwen3` | `qwen3` | 不变 |

`工具/serve.sh` 默认只监听 127.0.0.1，并把命令、版本、配置哈希、逐秒 GPU 状态和服务日志存到独立目录。

## 启动

CUTLASS（通过质量门槛时使用）：

```bash
NAME=final MAX_SEQS=8 LINEAR_BACKEND=cutlass MODEL_DIR=$HOME/uclode/models/Qwen3.8-27B-FP8-channel bash 工具/serve.sh start
```

Marlin（退路）：

```bash
NAME=final MAX_SEQS=8 bash 工具/serve.sh start
```

等价的 vLLM 命令（CUTLASS）：

```bash
vllm serve $HOME/uclode/models/Qwen3.8-27B-FP8-channel --host 127.0.0.1 --port 8088 --tensor-parallel-size 1 --dtype auto --gpu-memory-utilization 0.90 --max-model-len 40960 --max-num-seqs 8 --kv-cache-dtype fp8 --reasoning-parser qwen3 --served-model-name qwen3.8-27b-fp8 --linear-backend cutlass
```

## 启动后检查

```bash
bash 工具/serve.sh status
```

运行目录的 `startup_evidence.txt` 应该显示：

| 配置 | 选中的 kernel |
|---|---|
| CUTLASS | `CutlassFP8ScaledMMLinearKernel` |

正常启动约 1–3 分钟，全新机器首次 JIT 编译会更久。

## 已知现象

- **FP8 KV 校准警告。** 日志会提示 KV scaling factor 为 1.0、未校准 `q_scale`。这是模型本身的配置状态，本项目没有处理。
- **Marlin 的 weight-only 警告。** 这是实际路径，不是错误。
- **关停时的 `EngineDeadError`。** 服务收到 SIGTERM 时可能打出 ERROR 堆栈，发生在请求结束之后，不影响结果。
- **IFBench 客户端超时。** 赛方脚本的 IFBench 没有设置超时，OpenAI SDK 默认 600 秒，长回答会被反复断开重采。原因和处理见复验说明。
